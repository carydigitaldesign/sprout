# M3: time and threads

Date: 2026-11-02. Driver: Claude (Fable 5.1). Navigator: Andre.

## What exists now

- **Interrupts are on.** `arch::interrupts` wraps `sstatus.SIE` and the
  `sie` source bits. `kmain` enables them once the timer, PLIC and
  scheduler are up.
- **`SpinLock` masks interrupts while held** and restores the previous
  state on drop, so a lock taken by a thread and by an interrupt handler on
  the same hart cannot deadlock. `force_unlock` exists for the panic path.
- **The console is locked per line.** A `log::Line` holds the console lock
  from `line()` to `end()`, so lines from different threads and handlers
  never interleave. The panic handler force-unlocks it first, so a panic
  mid-line still reports.
- **Timer** (`time.rs`): 100 Hz tick from the SBI `TIME` extension, counter
  rate read from `/cpus/timebase-frequency` in the device tree (10 MHz on
  QEMU `virt`). `ticks()`, `now_ns()`, `sleep_ms()`.
- **PLIC** (`arch/riscv64/plic.rs`): priority, enable and claim/complete for
  hart 0's supervisor context, with a handler table. Supervisor external
  interrupts drain every pending source.
- **UART receive** (`arch/riscv64/uart.rs`): the ns16550's receive
  interrupt (source 10) pushes bytes into `console` and logs a
  `console_rx` event. The first external interrupt the kernel handles.
- **Context switch** (`arch/riscv64/context.rs`): saves `ra`, `sp` and
  `s0`-`s11`; a new thread's context points `ra` at a trampoline and `s0`
  at zero so backtraces end cleanly.
- **Scheduler** (`sched/mod.rs`): kernel threads with 16 KiB stacks, a
  round-robin run queue, a sleeping list, a blocked list, and a zombie list
  reaped by the next thread to run. The boot context is thread `main`;
  `idle` runs `wfi` only when nothing else is ready. The timer tick wakes
  due sleepers and preempts the running thread when another is ready.
- **Wait queues** (`sched/wait.rs`): `wait_while(cond)`, `wake_one`,
  `wake_all`. Enqueue and block happen with interrupts off, so no wake-up
  is lost on one hart.
- **Backtraces follow the current thread.** The scheduler tells the walker
  each thread's stack bounds on every switch.

## Decisions made along the way

- **Traps and switches share the thread's stack.** Preemption is a `yield`
  from inside the timer interrupt; the trap frame stays on the stack and is
  restored by `sret` when the thread runs again.
- **`idle` is separate from the run queue.** It never queues and is picked
  only when the queue is empty, so it never steals a time slice.
- **Threads are leaked `Box`es held as raw pointers** under the scheduler
  lock, freed by whichever thread runs next after they exit. Simpler than
  `Arc` for now; M4's kernel objects will own threads properly.
- **The scheduler lock is dropped before the switch.** `schedule` disables
  interrupts for the whole operation itself, so the lock's own restore does
  not re-enable them mid-switch.
- **100 Hz.** Coarse, cheap, and enough until something needs finer sleeps.
- **UART FIFO on, trigger level 14.** Found the hard way: with the FIFO off
  or the trigger level at 1, QEMU's 16550 reports almost no free space to
  its host side, and the Windows stdio backend drops bytes rather than
  waiting, so typed bursts lost characters. At 14 a burst of up to about
  15 bytes is safe; the MCP `serial_write` paces longer input in 8-byte
  chunks because the guest cannot drain faster than its vCPU runs.

## Known limitations

- Single hart. `Ptr`'s `Send` and the wait queue's lost-wakeup argument
  both lean on that; SMP (M8) revisits them.
- No priorities, no time accounting, no `join` handle: `join` polls with
  `yield_now`.
- The main thread's exit in run mode leaves one zombie unreaped until
  something else switches; harmless, it has no stack to free.
- A thread that panics takes the kernel down; there is no per-thread
  recovery.
