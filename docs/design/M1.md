# M1: traps, backtraces, an idling kernel

Date: 2026-11-02. Driver: Claude (Fable 5.1). Navigator: Andre.

## What exists now

- **Trap vector** (`kernel/src/arch/riscv64/trap.rs`). `stvec` points at
  `__trap_entry`, which saves all 31 general registers plus `sstatus`,
  `sepc`, `scause` and `stval` into a `TrapFrame` on the current stack,
  calls `trap_handler`, restores everything and returns with `sret`. The
  frame is 288 bytes and the layout is checked at compile time.
- **Trap policy.** Breakpoints (`ebreak`) are counted and skipped, which is
  how tests exercise the path. Any other exception logs a JSON `trap` event
  carrying the cause, `sepc`, `stval`, `sp` and a backtrace of the
  interrupted context, then panics. Interrupts are logged and ignored; none
  are enabled before M3.
- **CSR access** (`csr.rs`): a macro giving each register a module with a
  safe `read` and an `unsafe` `write`.
- **Backtraces** (`backtrace.rs`). The kernel is built with frame pointers.
  The walker reads the return address at `s0 - 8` and the caller's frame at
  `s0 - 16`, and stops at anything that is not a frame: outside the boot
  stack, misaligned, a return address outside the kernel image, or a caller
  frame below the current one. Boot sets `s0` to zero so every walk ends.
- **Panics carry frames** and a recursion guard: a panic while reporting a
  panic exits at once instead of looping.
- **The kernel idles.** After boot it logs `{"event":"idle"}` and parks on
  `wfi`. `cargo xtask run` treats hitting the timeout after that line as a
  normal end (exit 0); a session from the MCP `boot` tool stays up until
  `stop`.
- **Symbolization.** `cargo xtask symbolize ADDR...` resolves kernel
  addresses to function, file and line from the ELF's DWARF, in-process via
  the `addr2line` crate, inlined frames included. `xtask run` and
  `xtask test` collect every `frames` array they see and print one
  `{"event":"symbols",...}` line at the end; `test` also puts it in the
  summary. The MCP server gained a `symbolize` tool.

## Decisions made along the way

- **Traps use the current stack.** Correct while every trap comes from the
  kernel. M4 adds `sscratch` swapping for traps from user mode.
- **`ebreak` is the test probe.** It is the one exception that is cheap to
  recover from precisely, so it doubles as the register-preservation test.
- **In-process symbolization, not `llvm-addr2line`.** The `llvm-tools`
  component for the windows-gnu host ships no addr2line or symbolizer at
  all. The `addr2line` crate removes the external dependency on every host.
  Host tooling dependencies need no ADR; kernel ones still do.
- **Assembly symbols get `.type` and `.size`**, otherwise symbol-table
  lookups skip them and attribute their addresses to a neighbour.
- **Return addresses are probed one byte back** when symbolizing, so a
  frame names the call site rather than the instruction after it.

## Known limitations

- The backtrace walker only trusts the boot stack. Per-thread stacks at M3
  must tell it their bounds.
- A trap inside the panic handler (for example from a bad console) is
  reported as a second panic and exits; the first line is already out.
- Precompiled `core` has no frame pointers, so frames inside `core` are
  skipped (the chain survives because `s0` is callee-saved).
- A failing test still ends the run; later tests do not execute.
