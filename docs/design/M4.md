# M4: user mode and the self-describing kernel

Date: 2026-11-02. Driver: Claude (Fable 5.1). Navigator: Andre.

## What exists now

- **`lib/sprout-abi`**: the one place the kernel and userspace agree.
  Syscall numbers, `Error` codes, `Rights`, `ObjectType`, the user address
  layout, and `SYSCALLS`: a table describing every syscall (arguments,
  return, object type, rights needed, doc). The kernel implements it, the
  runtime wraps it, and `describe` renders it.
- **`lib/sprout-rt`**: `_start`, the `ecall` stub, typed wrappers, a
  `log!` macro over a fixed buffer, and a panic handler that logs and
  exits 101. Programs link `user.ld`, static and non-PIE at `0x10000`.
- **`user/init`**: exercises every syscall once, logs what the kernel says
  about itself, its own process and a VMO, and checks that the kernel
  refuses an out-of-range read, a closed handle and a kernel address. Its
  exit code is the verdict. `cargo xtask build` builds it first and the
  kernel embeds it (`user_image.rs`) until an initramfs exists (M6).
- **ELF loader** (`elf.rs`): header and `PT_LOAD` segments, static
  riscv64 executables only.
- **Objects and handles** (`obj/`): `Object` is an enum of `Arc`s
  (`Process`, `Vmo` so far). A `HandleTable` maps small integers to an
  object plus `Rights`; slot 0 is reserved so handle 0 can mean "the
  kernel" in `describe`. Closed slots are reused.
- **Processes** (`obj/process.rs`): `spawn(name, elf)` builds a user page
  table, loads each segment into a VMO mapped with the segment's
  permissions plus user access, maps a 64 KiB stack VMO below
  `USER_STACK_TOP`, gives the process handle 1 to itself, and starts a
  kernel thread that drops into user mode. `exit` records the code, clears
  the handle table (which breaks the process's self-reference) and wakes
  `wait`ers.
- **User page tables** (`PageTable::new_user`): the kernel's upper-half
  entries are copied in, so the kernel is mapped (supervisor only) in
  every process and a trap needs no table switch. Dropping a user table
  frees only its own half. The scheduler switches `satp` when the next
  thread's root differs.
- **Trap entry for user mode**: `sscratch` holds the thread's kernel stack
  top while user code runs and zero while the kernel runs; one `csrrw`
  tells the two apart. The frame records the interrupted stack pointer
  either way, and returning to user mode re-arms `sscratch`.
- **Syscalls** (`syscall/`): `ecall` from user mode is dispatched with
  interrupts on, so a syscall may sleep or block like kernel code. Nine
  syscalls: `log`, `exit`, `yield`, `sleep`, `describe`, `handle_close`,
  `vmo_create`, `vmo_read`, `vmo_write`. Every user pointer is checked
  page by page against the process's own table (user-accessible, and
  writable where the kernel writes) before a copy; copies run with
  `sstatus.SUM` set.
- **`describe`**: JSON for the kernel (name, version, object types, every
  syscall with its schema) or for a handle (type, the holder's rights,
  type-specific fields, and the operations that apply with an `allowed`
  flag per the rights). The schema comes straight from `sprout-abi`.
- **Fault isolation**: an exception in user mode logs a `user_fault`
  event and kills the process with exit code 128 + cause. The kernel
  lives on.
- **JSON writer** (`json.rs`): the log line builder was generalised over
  any `fmt::Write` sink with proper nesting, so `describe` builds into a
  `String` with the same code the console uses.

## Decisions made along the way

- **The schema is a `const` table in `sprout-abi`**, not derived from the
  implementation. Both sides compile against it; the kernel's `describe`
  test checks every entry is rendered.
- **Objects are an enum of `Arc`s** rather than trait objects. Few types,
  exhaustive matches, no vtables.
- **A process's first handle is itself.** It gives `init` something to
  describe and sets the pattern: capabilities arrive at spawn, nothing is
  ambient. The self-reference is a cycle, broken by clearing the handle
  table at exit.
- **Syscalls run with interrupts on.** The trap handler enables them
  around `dispatch` so `sleep` and future blocking calls work unchanged.
- **Syscall `exit` must drop its process reference by hand.** The thread
  never returns, so nothing on its stack is dropped; the first test run
  leaked exactly one process (28 frames) until the `Arc` was released
  before leaving the scheduler. The free-frame assertion caught it.
- **`SUM` stays set** for the whole time a user thread is in the kernel.
  Narrowing it to the copy routines is cheap and can come with the
  security pass.

## Known limitations

- One thread per process; no `Thread` or `AddressSpace` objects yet. The
  `ops` list for a process is empty because no syscall targets one.
- Registers are not scrubbed on the way into user mode, and floating-point
  state is not saved across traps or switches: user programs must not use
  floats until that lands.
- No handle transfer between processes; that is the channel work of M5.
- `log` from user mode is capped at 512 bytes, so `init`'s echo of the
  kernel description is cut short in the console. The description itself
  is complete; `init` checks its full length.
- `init` is embedded in the kernel image, so changing it rebuilds the
  kernel. Fine until the initramfs.
