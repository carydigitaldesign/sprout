## Slice 1: a bootable preview (2026-11-02)

Goal: something a person can boot and watch without a serial port. Two
pieces.

### VGA text console on x86_64

`kernel/src/arch/x86_64/vga.rs`: the 80 by 25 text buffer at physical
0xB8000, light grey on black, wrapping long lines and scrolling. Every
byte the kernel logs now goes to COM1 and the screen; the boot event
reports `"console":"com1+vga"`. `map_platform` keeps the buffer in the
direct map after `mm::init` replaces the boot tables. The screen state
has no lock of its own: `console_putc` is only called by the log writer
under the console lock, which also masks interrupts, and the module says
so.

JSON log lines are longer than 80 columns, so the screen shows them
wrapped. It is a boot log, not a terminal; a terminal needs a keyboard
and a program to talk to, neither of which exists yet.

### A GRUB ISO from CI

`tools/mkiso.sh` builds the release x86_64 kernel, strips its debug info
(GRUB loads none of it, and it is most of the file) and runs
`grub-mkrescue` with a one-entry `grub.cfg`. GRUB speaks Multiboot 1 and
honours the a.out kludge fields the header already carries, so the same
image QEMU boots with `-kernel` boots from the ISO with no kernel change.

The tools are Linux packages, so CI's new `iso` job builds the ISO on
Ubuntu, boots it in QEMU and waits for `init done, ok=true` on the
serial line, then uploads it as the `sprout-x86_64-iso` artifact of every
green push. On Windows the script runs from WSL.

### A fix on the way

`time::sleep_ms` promised "at least" by counting ticks, which holds when
the tick and the fine clock are the same counter (riscv64) and not when
they are two oscillators (x86_64: PIT and TSC). The PIT divisor rounded
down, so a tick was 0.7 µs short of 10 ms and a 20 ms sleep measured
19.997 ms. The divisor now rounds up, the TSC is calibrated against the
PIT's real period, and `sleep_ms` checks the fine clock and tops up a
tick at a time.

### What the ISO does and does not do

- Boots on BIOS machines and in VirtualBox, Hyper-V Generation 1 and
  QEMU; shows the boot and `init`'s checks on screen; then idles.
- No UEFI boot (Multiboot 1 is BIOS-only; ADR-0007). No keyboard. No
  disk or network on x86_64 until virtio-pci exists, so no `mcpd` and no
  MCP endpoint from the ISO. The riscv64 QEMU run remains the full
  system.
